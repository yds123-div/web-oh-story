### 5b. 走查中发现但**未修**的一件事（不是谎报，是死分支）

`AssetsPage.tsx` 里生成资产形象时会带 `base64: asset.imageUrl?.startsWith('data:') ? asset.imageUrl : null`，
注释写着「参考图仅限本地上传的 data URL」。**这个分支实际永远走不到**：上传成功后
`onFileSelected` 会 `await loadList()` 重拉列表，`asset.imageUrl` 已被换成后端的 `/oss/...` 静态路径，
而 `getAssetsApi` 回来的 `src` 从来不是 data URL。即「上传图片 → 生成形象」并不会把上传图当参考
送给后端（后端 `generateAssets` 本身是支持 `base64` 参考图的）。

**为什么没修**：修它要么让后端按 assetsId 自己回读 `o_image`（改后端业务代码，超出工单范围），
要么前端把 OSS 图取回来转 base64——后者会改变「重新生成形象」的语义（从纯文生图变成图生图），
属产品决定，不适合在验收工单里悄悄改。页面上**没有任何文案承诺**上传图会当参考用，
所以这不是「谎报成功」，只是一段无效分支；已在代码注释里把实情写清楚，留给你决定要不要接。

（同理，分镜那侧的 `getAssetsImageBase64` 链路是后端真实可用的，但分镜的 `associateAssetsIds`
UI 无法设置——这是 issue 09 就记过的既有缺口。）
