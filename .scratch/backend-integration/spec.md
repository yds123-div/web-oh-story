# 规格：DeepSFV 前后端对接（以后端为主）

> 状态：已与用户达成共识，可由 agent 领取实施（ready-for-agent）
> 日期：2026-09-22

## Problem Statement

DeepSFV 前端（"AI 短剧创作工坊"，React 19 + AntD 5 单页应用）目前由 MSW mock 驱动：所有 `/api/*` 请求被拦截到内存假数据库，另有 5 个页面直接渲染硬编码常量。用户在页面上看到的一切数据都是假的，无法进行真实的创作工作流。

后端是一个从 Toonflow 迁移而来的 Express 5 + SQLite 服务，拥有 169 个真实接口（项目/剧本/小说/资产/分镜/工作台/任务/设置等），但前后端是**两套独立设计的契约**，天然不通：

- 前端期望 REST 风格（GET/PATCH、路径参数），后端几乎全是 POST + 动作路径（如 `POST /api/project/getProject`）
- 前端按 HTTP 状态码判断成败，后端永远返回 HTTP 200，用信封 `{code: 200/400, data, message}` 表达成败
- 后端全局强制 JWT 鉴权，前端没有登录页，token 是占位符
- 领域模型不同构：前端"大纲→资产→分集→片段"，后端"剧本→资产→分镜→视频轨道/工作台"
- 前端开发代理默认指向 8080，后端固定监听 10588

## Solution

在前端建立唯一的适配层（API client 模块重写），把页面所需的全部数据操作接到后端真实接口上。前端按后端实际能力裁剪/调整页面。完成后，在本地（前端 5173 + 后端 10588）端到端跑通核心创作主线：**新建项目 → 提交剧本 → 提取资产 → 管理资产 → 分镜 → 工作台提示词生成**，全程使用真实数据（不导入种子数据，用真实流程现造数据）。

核心原则：**后端为主**。三条冲突裁决规则：

1. **数据结构冲突**（字段名/结构不一致）→ 改前端适配层，不改后端
2. **能力冲突**（前端有某功能、后端无对应接口）→ 该功能隐藏或降级，不新增后端接口
3. **语义冲突**（同一概念两边定义不同）→ 以后端为准

## User Stories

### 骨架（P0）

1. As a 创作用户, I want 打开首页就能看到后端数据库里真实的项目列表, so that 我知道我的工作都存在哪里
2. As a 创作用户, I want 新建项目时表单选项（类型/画风/画幅/图像模型/视频模型等）与后端字段一一对应, so that 项目配置能被完整保存并在下次打开时还原
3. As a 创作用户, I want 重命名和删除项目立即持久化到后端, so that 刷新页面后变更不丢失
4. As a 创作用户, I want 首页的项目计数（角色数/剧本数/视频数/分镜数）来自后端统计接口, so that 我掌握每个项目的真实进度
5. As a 创作用户, I want 应用启动时静默完成认证并持有合法 token, so that 所有接口调用不被 401 拦截，且我不需要面对登录界面
6. As a 创作用户, I want 在创作页粘贴剧本文本并提交后，剧本被真实保存到后端, so that 我的剧本不会因为刷新而消失
7. As a 创作用户, I want 剧本列表展示后端真实剧本并可编辑/删除, so that 我能管理已提交的剧本
8. As a 创作用户, I want 资产工坊展示当前项目的真实资产列表（角色/场景/道具）, so that 我看到的是 AI 提取或手工创建的真实资产
9. As a 创作用户, I want 手工新增/编辑/删除资产并立即持久化, so that 我能修正 AI 提取结果
10. As a 创作用户, I want 上传资产图片（base64 保存）后能在资产卡上看到它, so that 资产有视觉形象
11. As a 创作用户, I want 后端接口业务失败（信封 code≠200）时看到统一的错误提示, so that 我知道操作没成功而不是页面悄悄没反应
12. As a 创作用户, I want 网络错误和后端不可达时有明确提示, so that 我能区分"服务没起"和"操作出错"
13. As a 创作用户, I want 异步任务（提取资产、生成图片、生成视频）的提交与轮询接通后端任务体系, so that 任务状态（进行中/成功/失败）反映真实进度
14. As a 创作用户, I want 任务中心页展示后端任务表的真实任务（含分类、项目归属、失败原因）, so that 我能追踪所有后台任务
15. As a 开发者, I want 关闭 MSW、开启开发代理并指向后端真实端口后前后端直接连通, so that 不需要逐页改请求代码
16. As a 开发者, I want MSW mock 体系保留在测试中使用, so that 组件测试依然可以不依赖真实后端运行
17. As a 开发者, I want 前端页面组件的调用代码尽量不动、只重写 API client 内部实现, so that 对接工作的回归风险集中在唯一一层

### 文本 AI 与分镜链路（P1）

18. As a 创作用户, I want 对剧本执行 AI 提取资产（可用文本模型）并轮询提取结果, so that 我不用手工从剧本里抄角色和场景
19. As a 创作用户, I want AI 润色资产提示词（可用文本模型）, so that 资产描述更适合后续生图
20. As a 创作用户, I want 资产 AI 生图接口接通（图像 key 到位前调用会失败）, so that key 一配好这个功能立刻能用
21. As a 创作用户, I want 生图失败的资产有清晰的失败态展示和原因说明, so that 我知道该重试还是该改提示词
22. As a 创作用户, I want 分镜的增删改查接通后端分镜接口, so that 片段工作室里的分镜数据是真实持久的
23. As a 创作用户, I want 分镜图片的批量生成、轮询、预览、下载接通, so that 分镜有画面可看
24. As a 创作用户, I want 工作台视频轨道的创建/删除/列表接通, so that 视频生成准备工作是真实的
25. As a 创作用户, I want 用 AI 生成视频提示词（可用文本模型）, so that 每个分镜轨道有可用的生成提示词
26. As a 创作用户, I want 视频生成接口接通（视频 key 到位前调用会失败）并有失败态, so that key 一配好这个功能立刻能用
27. As a 创作用户, I want 视频生成成功后能在轨道上选择/切换生成的视频, so that 我能挑最满意的一版
28. As a 创作用户, I want 工作流数据（FlowData 整体存取）接通, so that 我在工作室页的编辑状态能整体保存和恢复

### 降级与裁剪

29. As a 用户, I want 后端不存在的功能（模板列表、通知、积分、存储用量）从界面上隐藏而不是报错, so that 界面上可见即真实可用
30. As a 用户, I want 纯浏览型页面（画布管理、资产广场、空间页）暂保留现有静态内容, so that 主线联调期间导航结构完整
31. As a 用户, I want 创作页的"小说模式"入口暂时隐藏、只保留剧本模式, so that 可见功能都有真实后端支撑
32. As a 用户, I want 创意对话页暂隐藏或降级, so that 它在后端能力（Socket.io Agent / 图片编辑工作流）对接前不误导我
33. As a 创作用户, I want 空列表/空项目时有友好的空状态引导, so that 第一次打开真实后端（数据库为空）不至于看到白屏

## Implementation Decisions

### 总体

- **后端为主**：169 个接口是事实标准，本次不改后端任何业务代码（唯一例外：无——鉴权通过前端静默登录解决，而非后端放开白名单）
- **适配层放前端**：重写前端 API client 模块（约 25 个函数）的内部实现，页面组件的调用方式尽量不变
- **不分期实现为一个整体，但按 P0 → P1 → P2 顺序交付**（P2 见 Out of Scope）
- 不导入种子数据；联调数据用真实流程现造（这本身是最真实的端到端验证）

### HTTP 请求层改造

- 请求层增加**信封适配**：解包 `{code, data, message}`，`code !== 200` 时抛出携带 message 的错误对象；HTTP 非 2xx 与网络错误沿用现有错误处理
- 全部请求改为 **POST + JSON body**（后端除少数 GET 外全是 POST）；前端现有的 REST 动词/路径参数语义在 API client 内部翻译
- 认证：应用启动时**静默自动登录**（默认账号 admin/admin123 调用登录接口，真实 token 存入现有 localStorage 键），用户无感；后续做登录页时直接替换这一步
- 401 处理沿用现有全局提示机制

### 环境与代理

- 前端默认环境变量切换为：关闭 MSW、开启开发代理、代理目标指向后端真实端口 10588
- MSW 代码保留在代码库中，用于测试（不再默认启动于应用）

### 领域概念映射

| 前端概念 | 后端概念 | 说明 |
|---|---|---|
| 项目 | 项目（o_project） | 字段名适配（类型/画风/画幅/模型选择等） |
| 剧本大纲 | 剧本（o_script） | 创作页提交 → 剧本新增；大纲工作台的数据源改为剧本 |
| 资产 | 资产（o_assets） | 类型枚举映射（角色/场景/道具）；图片走 o_image |
| 分集 | 剧本即分集 | 前端"分集列表"概念改造为后端"剧本列表"形态（本次页面形态可以简单） |
| 片段/分镜 | 分镜（o_storyboard） | 片段工作室的分镜编辑对接后端分镜接口 |
| 视频生成 | 工作台轨道（o_videoTrack/o_video） | 视频选择/列表对接工作台接口 |
| 任务 | 任务（o_tasks） | 前端"提交任务→轮询 getTask"模型适配为后端任务体系 + 各业务自带轮询接口 |
| 模板/通知/积分/存储用量 | **后端没有** | 前端隐藏 |
| 小说模式 | 后端有完整小说链路 | 本次隐藏入口，二期接 |
| 创意对话 | 后端有 Socket.io Agent 与图片编辑工作流 | 本次隐藏/降级，二期接 |

### AI 生成能力现状

- 后端 AI 供应商默认全部禁用、未配 key；用户**已有文本模型 key**（P1 开始时提供供应商名与 key，通过后端供应商配置体系配好）
- 文本 AI 链路（剧本提取资产、提示词润色/生成）在 P1 可真实联调
- 图像/视频生成接口在 P1 **接好但调用会失败**（key 未到位），必须做好失败态：明确错误原因展示、可重试、不阻塞页面
- 后端文件访问走其静态托管路径（/oss 等），前端展示的图片/视频 URL 直接使用后端返回的路径

## Testing Decisions

- **唯一主接缝：前端 API client 的公共函数接口。** 页面组件通过这些函数获取数据；对接的全部翻译逻辑（REST→POST、信封解包、字段映射、任务模型转换）都收敛在这一层之下。理想接缝数量 = 1，本次不新增第二层抽象。
- 测试方式：用 MSW 的 node 模式模拟**后端真实契约**（正确的 POST 路径、JSON body 形状、`{code, data, message}` 信封、失败信封），对 API client 函数断言两件事：
  1. 发出的请求形状正确（路径、方法、body 字段名与后端校验器一致）
  2. 返回值已正确翻译为前端类型（信封解包、字段映射、错误抛出）
- 好的测试只测**外部行为**：请求形状 + 返回值形状 + 错误行为；不测内部实现细节（如何组织翻译函数等）
- 少量页面级集成测试（Vitest + Testing Library + MSW）验证关键页面能用翻译后的真实契约渲染（项目列表页、资产工坊各一）
- 现有参考：前端已有 Vitest + jsdom + Testing Library + MSW 测试体系；mock handlers 中已有参数校验式写法可沿用
- 端到端验收：本地起真实后端 + 前端，走一遍"新建项目→提交剧本→提取资产→编辑资产→分镜→提示词生成"，全程无 mock

## Out of Scope

- **登录页**（只做静默自动登录；正式登录页后置）
- **服务器部署**（本地跑通为先，nginx/容器部署后续单议）
- **种子数据导入**（后端库保持真实数据）
- **P2 全部内容**：小说链路 12 接口、Socket.io Agent 对话（scriptAgent/productionAgent）、图片编辑工作流（editImage）、音频/配音（audioAssets/cornerScape）、设置系统（供应商配置页/modelMap/promptManage/skillManage/agentDeploy）、导演手册/视觉手册、Agent 记忆/计划数据
- **后端任何业务代码修改**（含把明文密码、CORS 全开等安全问题——已记录在 Further Notes，但不在本次范围）
- 桌面端遗留接口（更新检查/文件管理）、数据库管理接口（有清库风险）、健康检查外的测试接口
- 画布管理/资产广场/空间页的**真实化**（本次保留静态内容，二期）

## Further Notes

- 后端要求 Node >=18；开发启动命令为后端 `yarn dev`（端口 10588）、前端 `pnpm dev`（端口 5173）
- 后端 token 有效期 180 天，本地联调期间无需处理过期
- AI 生成依赖后端供应商配置：文本模型 key 由用户在 P1 开始时提供（供应商名 + key），通过后端供应商配置体系写入；图像/视频 key"不久会有"，到位后无需改代码即可激活对应链路（接口已接好）
- 前端三步工作流门控（大纲定稿→资产完成→分集解锁）依赖的概念在后端没有直接对应（如"大纲定稿"状态），P0/P1 期间门控逻辑需按后端真实状态字段重新映射或临时放宽，实施时与用户确认具体门控规则
- 已知后端安全点（本次不处理，留档）：用户密码明文存储、CORS 全开、JWT 密钥存于数据库
- 后端有一处疑似占位接口（getTextModel 固定返回"123"），对接时绕过即可
